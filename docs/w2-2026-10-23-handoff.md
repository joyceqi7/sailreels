## 套餐接口与数据迁移

- 新增 `GET /api/v1/dramas/{id}/episodes/{seq}/unlock-options`，返回三档数量、集数、价格和可选状态。
- `POST /api/v1/orders/beans` 支持 `quantity=1|3|10`（默认 1）及可选 `expected_token_amount`。
  前端不决定价格；已拥有、缺集、越界、价格变化均在后端重新检查。套餐不跳过已拥有集后另找其他集，
  而是禁止出售该范围，避免对已拥有的内容重复计费。
- `beans_orders.episode_seqs` 保存建单时的准确发货范围；既有 NULL 订单继续按单集 `seq` 发货。
- `673a789fcd7d` 迁移由 Alembic 在隔离 SQLite 中自动生成并人工检查，新增 nullable JSON，不回写旧订单。
  CI 另行在 PostgreSQL 16 从头迁移。合并部署时必须先执行 `alembic upgrade head`（现有容器启动已执行）。
- Webhook 同一事务更新订单并发完套餐所有集；任意一集失败则全部回滚，由现有重试任务补发。
- 上游异常时，如果本地订单已经创建，返回错误码及业务 `order_id`，页面保留原订单查询入口。
  上游异常发生在价格校验前、尚未建单时不返回订单引用。
- 回退代码前先核对已创建的套餐订单，不能直接删除快照列后用旧代码发货，否则可能只发第一集。

## 页面与模拟边界

首页 → 详情 → 剧场；页面只保存元数据，播放身份来自权限响应。SDK 只使用官方 `getPlayer()`，
没有引入其他播放器或视频 URL 旁路。单集切换成功才提交当前集状态，异步结果晚于页面卸载时不会再切集。

`mock` 模式提供明确标识的预览支付和广告面板，且不调用真实支付/广告：成功/取消/延迟/错误、
完播/提前关闭/错误分别测试。`live` 模式使用实际 API 和 SDK，不显示预览控制。
Mock 权益只在内存中，不能影响真实后端，也不生成用户 session。
官方样例只有 3 集，末尾不足 3/10 集时套餐禁用；三档实际发货由 12 集后端测试和 live 页面测试覆盖。

处理中订单在同一页面生命周期内关闭/重开面板可恢复；恢复前通过 API 校验订单归属。
服务器确认已支付但 access 未就绪时，继续保留订单查询，防止再买一次。
完整刷新后的订单历史、完全断网丢失响应的恢复和主动对账仍属于后续开发，不能据超时断言未建单。
